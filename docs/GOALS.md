# 目标文档 (GOALS)

> 语言名: **Sole** · 版本: v0.1 (草案) · 状态: 设计阶段
>
> 本文档是语言的"宪法"。所有后续的语法参考手册、标准库设计、实现决策都必须与本文档保持一致;若发生冲突,要么修改决策,要么修改本文档(并记录理由)。

---

## 1. 愿景与定位 (Vision & Positioning)

**一句话定位:**

> 一门面向"人类与 AI 协作编程"的静态类型、缩进式通用语言 —— 语法取 Python 与 TypeScript 之长,
> 语义上消灭一切隐式魔法,让代码行为完全可预测。

### 1.1 目标用户

| 用户 | 需求 |
|------|------|
| 人类开发者 | 读代码快、心智负担小、工具链完善 |
| AI 编码代理 (Copilot / Claude Code / Codex 类) | 生成代码一次通过率高、报错可定位、格式唯一、无歧义 |
| 两者协作 | 人类审阅 AI 代码时,能快速理解其意图与边界 |

### 1.2 核心场景

**暂定: 通用场景 (General Purpose)** —— 不预先绑定领域;后续出现具体需求时再收缩定位(2026-08-11)

**通用定位的现阶段含义:**
- 不排除也不承诺任何领域;标准库做平衡的核心集,优先级由后续实际需求驱动(见 §8)
- 保留若干**软性偏好**(来自此前的脚本定位讨论,不设硬性指标):
  - 启动快、无构建步骤的开发反馈环(执行前一次性完成 解析 → 类型/借用检查 → 字节码)
  - shebang 支持(`#!/usr/bin/env sole`),脚本可直接执行,无 `main()` 仪式
  - 报错信息直接可读、可行动(§9.2 不变——对任何场景都是刚需)
- 所有权与静态类型带来的"正确性优先"特征是语言的身份,不随场景收缩而改变

### 1.3 非目标 (Anti-Goals)

以下内容**明确不做**,防止范围蔓延:

- ❌ 不做高性能系统编程(不与 C/Rust 竞争原始性能;选择所有权是为"无 GC 的确定性",而非性能竞赛)
- ❌ 不做运行时元编程 / 宏系统 / 代码生成反射(与"显式优于隐式"冲突)
- ❌ 不追求语法糖丰富度(糖越少,AI 越不容易写错)
- ❌ 不兼容 Python/TS 源码(不假装自己是它们的方言)
- ❌ 不做动态类型语言(类型是 AI 自我检查的第一道防线)

## 2. 核心设计原则 (Principles)

每条原则都必须**可执行、可验证**,不是口号。

### P1. 单一明显方式 (One Obvious Way)
同一件事只允许一种主流写法。语言层面(而非靠社区规范)尽可能排除等价写法:
- 没有两种循环关键字(`for` 只有一种形态,不学 C 的 `for/while/do-while` 三件套)
- 没有两种相等写法(禁止 `==` 之外再来一套 `is`/`eq`)
- 新增特性前自问: "这个写法是否已经有等价方案?"——有则不加

### P2. 可预测性 (Predictability)
- 语法无歧义、非上下文敏感(解析不依赖"前一行是什么")
- 求值顺序确定(不做依赖实现细节的未定义行为)
- 同一段代码永远有相同含义,不随导入、全局状态变化

### P3. 显式优于隐式 (Explicit Over Implicit)
- **禁用魔术方法**(详见 §5): 没有 `__add__`、`__eq__`、`__iter__` 这类隐藏钩子
- 无隐式类型转换(数值类型间转换也必须显式调用)
- 无隐式全局导入、无隐式单例、无隐式作用域穿透

### P4. 可读性优先于书写便捷 (Readability First)
代码被阅读/审阅的次数远多于被书写的次数,尤其 AI 生成的代码会被人反复审阅。

### P5. 静态类型,强推断 (Static + Inferred)
- 局部变量尽量推断,公开签名必须显式标注(公开 API 是契约,契约必须看得见)
- 类型错误必须在编译期报出,并给出**可定位、可修复**的错误信息

### P6. AI 生成友好 (AI-Generation Friendly)
可量化的目标:
- 常见任务上,AI 生成的代码**一次编译通过率 ≥ 90%**
- 编译错误信息包含: 精确位置 + 原因 + 修复建议 + 示例
- 语言自带唯一格式(formatter),AI 不需要猜测风格

### P7. 最小核心,可靠标准库 (Small Core, Solid Stdlib)
语言核心特性少而稳;能力主要来自小而精的标准库,而非语法。

## 3. 语法决策 (已定)

> 本节记录已拍板的语法决策及其动机。**已定 = 除非发现致命缺陷,不再更改。**

### D1. 缩进式块结构 (Indentation-Based Blocks)
- 类 Python: 缩进定义代码块,无 `{}`、无 `end` 关键字
- 理由: 视觉结构直接、token 更少、AI 对齐嵌套结构更可靠
- 硬性规则:
  - 混用 Tab/空格 = **编译错误**(不是警告)
  - 表达式跨行仅在括号内允许(同 Python 规则),禁止隐式行连接
  - 行尾无分号;一行一个语句(`;` 可保留为显式同行分隔,但 formatter 会展开)

### D2. 后置静态类型 (Postfix Static Types)
- 类 TypeScript: `x: int`、`fn add(a: int, b: int) -> int`
- 签名从左到右自然阅读: 参数名在前、类型在后,读起来像英文句子
- 规则:
  - **函数/方法公开签名必须显式标注类型**(AI 与人都需要可见契约)
  - 局部变量可推断,标注可省略:`let x = 5`
  - 推断是类型别名友好式的(推断出的类型与手写标注完全等价,不做渐进式)

### D3. 禁用魔术方法 (No Magic Methods)
- **彻底禁止** Python 式 `__xxx__` 隐藏钩子
- 语言不提供任何"定义符号后自动生效"的机制
- 替代机制见 §5 —— 这是本语言与 Python 最大的分水岭

### D4. 方括号泛型 (Square-Bracket Generics)
- 类 Python 风格: `List[int]`、`Dict[str, int]`、`Result[Ok, Err]`
- 理由: 避免 `<>` 与比较运算符/移位符的歧义(TS 与 JSX 的著名痛点),AI 生成时不会写错方向
- 解析规则(保证无歧义):
  - 泛型参数**只出现在类型位置**(类型标注、类型别名、泛型约束内)
  - `[]` 下标索引只出现在表达式位置
  - 两个位置语法上下文天然区分,无需二义性回退

### D5. 命名约定 (待定,建议如下)

| 类别 | 建议 | 理由 |
|------|------|------|
| 函数/变量/字段 | `snake_case` | 与 Python 生态一致,AI 语料最丰富 |
| 类型/接口/枚举 | `PascalCase` | 与 TS 一致,类型位置一眼可辨 |
| 常量 | `SCREAMING_SNAKE` | 惯例 |
| 方法 | `snake_case` | 统一 |

> 注: 单一命名规则本身就是 AI 友好 —— 模型无需猜测某个名字的风格。

### D6. 循环形态: `for` + 显式迭代 + 所有权标记 (Loop Form)

**唯一集合循环**: `for x in <iterable>`,由"迭代对象 + 所有权标记"决定语义(已定 2026-08-11)

| 写法 | 语义 | 循环变量类型 | 翻译为 |
|------|------|------|------|
| `for x in v` | **移动迭代**: 消耗 v 的所有权,循环后 v 不可再用 | `T` | `v.into_iter()` |
| `for x in ref v` | **借用迭代**: 不消耗,v 循环后仍可用 | `ref T`(Copy 元素则直接为值) | `v.iter()` |
| `for x in mut ref v` | **可变借用迭代**: 可经 x 修改元素 | `mut ref T` | `v.iter_mut()` |

- 三种标记对应三种**不同的语义**(消耗 / 只读 / 修改),不是等价写法,不违背 P1
- **无隐式迭代**: `for` 只接受显式实现了迭代接口的类型(见 §5 `__iter__` 行);标记被翻译为对应的具名接口方法调用 —— 是接口契约,不是语法魔法
- **Copy 元素规则**: 借用迭代中,`int`/`float`/`bool` 等 Copy 元素的循环变量直接为值(读取即复制,无副作用;该规则在 spec 中明确定义)
- **条件循环**: 仅保留 `while <cond>:` + 缩进块 一种(条件驱动与集合驱动语义正交,不算等价写法;Python 亦如此)
- 循环变量默认不可变;`for mut x in ...` 允许循环体内重新绑定(与 `let mut` 一致)

**设计理由(对 AI 友好)**: 所有权在循环这一最常用的构造上完全可见 —— AI 生成的循环不会悄悄消耗掉调用者还在使用的集合;编译错误会立刻指出,并提示改成 `ref`。

### D7. 可变性: 默认不可变 + 显式 `mut` (Mutability)

- **绑定默认不可变**: `let x = 5` 不可重新赋值;`let mut x = 5` 可重新赋值
- **参数默认不可变**: `fn f(x: int)` 内不可改 x;需要时 `fn f(mut x: int)`(`mut` 在名字前,与 `let mut` 一致)
- **字段可变性随绑定**(Rust 模型,初版无字段级 `mut`): `let mut s = ...` 可改 s 的字段;`let s = ...` 一律不可改 —— 少一个概念,借用检查也简单
- **两类 `mut` 并存,层次不同**(文档明确区分):
  - 绑定层: `let mut` / 参数 `mut x` —— 修饰"名字可重新绑定"
  - 类型层: `mut ref T`(见 §6)—— 修饰"借用可变"
- 标准库可变容器(`List[T]` 的 `push`/`set` 等)要求持有者是**可变绑定或可变借用**,编译期强制

**设计理由(对 AI 友好)**: 默认不可变让 AI 生成的代码天然少一类 bug(意外改写共享数据);`mut` 的出现位置即文档,读代码 = 理解可变性边界。

## 4. 类型系统目标 (Type System)

### 4.1 基础类型
- 数值: `int` (任意精度)、`float` (IEEE 754)、可选 `i32/u32/i64` 等定宽类型(待定)
- `bool`、`str` (不可变、UTF-8)、`bytes`
- 容器: `List[T]`、`Dict[K, V]`、`Set[T]`、`Tuple[...]`、`Range`、`Chan[T]`(见 §7)

### 4.2 关键语义决策

| 主题 | 决策 | 说明 |
|------|------|------|
| 空值 | **无 null/nil 字面量**,用 `Option[T]` | null 是 AI 生成代码 bug 的头号来源;`Option` 强制处理 |
| 错误处理 | **显式 `Result[T, E]` 返回**,不用异常 | 异常是隐式控制流;`Result` 让错误路径看得见 |
| 相等性 | 值类型=结构化相等;引用类型=引用相等,自定义须显式 `equals()` | 无 `__eq__` 魔法,相等行为永远可预测 |
| 隐式转换 | 一律禁止 | 数值提升也须显式(如 `float(x)`) |
| 泛型 | 方括号、支持约束 (`T: Comparable`),泛型仅编译期展开 | 无运行时泛型魔法 |
| 接口 | 显式 `interface`,实现须显式声明(无鸭子类型隐式实现) | 与"禁用魔术方法"一致 |
| 可变性 | 默认不可变,显式 `mut`(详见 D7) | AI 生成的代码默认安全;`mut` 出现位置即文档 |

### 4.3 不做
- ❌ 无依赖类型、无高阶类型、无类型级编程(对 AI 生成是负担)
- ❌ 无运行时反射式类型检查(保留有限的 `type(x)` 查询,待定)

## 5. 魔术方法政策 (Magic Method Policy)

> 这是全文档最重要的章节: 定义了"禁用魔术方法"的具体替代方案。
> 原则: **任何行为要么是语法内置的,要么是显式方法调用,不存在第三态。**

| Python 魔法 | 本语言的替代 | 示例 |
|-------------|-------------|------|
| `__add__` 等运算符重载 | **自定义类型禁止运算符重载**;运算符仅作用于标准库类型。自定义类型操作一律显式方法 | `a.add(b)` 而非 `a + b` |
| `__eq__` / `__hash__` | 值类型自动结构化相等;引用类型默认引用相等,自定义比较用显式 `equals()` | `a.equals(b)` |
| `__str__` / `__repr__` | 显式 `.to_str()` 方法(由标准库接口约定,不自动触发) | `print(x.to_str())` |
| `__iter__` | 显式实现迭代接口;`for` 只接受该接口,且**所有权标记决定迭代方式**(见 D6): `into_iter()` / `iter()` / `iter_mut()` | `for x in ref items` |
| `__getitem__` / `__setitem__` | 仅内置容器支持 `[]`;自定义类型用显式方法 `get(k)` / `set(k, v)` | `cache.get(key)` |
| `__len__` | 显式 `.len()` 方法 | `items.len()` |
| `__enter__` / `__exit__` | 资源管理用 `with` 块 + 显式接口 `Resource { open(), close() }` | `with file` |
| `__call__` | 函数对象必须显式字段持有(`callable: Fn`),无隐式可调用实例 | `handler.call(args)` |
| `__getattr__` / 动态属性 | **不存在**。无运行时属性拦截 | — |

**设计理由(对 AI 友好):**
1. 隐藏钩子 = AI 幻觉重灾区。模型看到 `a + b` 时无法确定 `a` 是否实现了 `__add__`,行为不可预测
2. 显式方法名让"读代码 = 理解代码",审阅 AI 生成代码的成本大幅下降
3. 语义边界清晰: 运算符只干一件事,方法就是方法

**权衡(诚实记录):**
- 代价: 自定义类型的表达式写法更啰嗦(`matrix.multiply(other)` 而非 `m1 * m2`)
- 缓解: 标准库提供 `Matrix` 等常用类型,把重载的便利保留在标准库内;自定义类型提供实用的组合子方法

## 6. 内存与所有权模型 (Ownership Model)

> 作者决策: **所有权模型,无 GC**。GC 的暂停与不确定性不可接受。
> 硬性约束: **不引入 Rust 的 `&`、`&mut`、`'a` 生命周期符号** —— 所有权语义保留,视觉负担归零。

### 6.1 设计: 无符号所有权

| 需求 | Rust 写法 | Sole 写法 |
|------|-----------|-----------|
| 不可变借用参数 | `fn f(x: &T)` | `fn f(x: ref T)` |
| 可变借用参数 | `fn f(x: &mut T)` | `fn f(x: mut ref T)` |
| 生命周期标注 | `fn f<'a>(x: &'a T) -> &'a T` | **无需标注**;编译器推断返回借用源自输入借用 |
| 结构体持有引用 | `struct S<'a> { x: &'a T }` | **禁止**;改用 `Shared[T]` 或移入所有权 |
| 共享数据 | `Rc<T>` / `Arc<T>` | `Shared[T]`(标准库,引用计数) |
| 字符串切片 | `&str` | 无切片借用;`str` 为 COW 值类型(见 6.3) |

### 6.2 核心规则

1. **移动语义默认**: 赋值、传参、返回值默认移动(非 Copy 类型),无需任何符号
2. **Copy 类型**: `int`/`float`/`bool` 等 POD 自动复制(语言内置,无 `Copy` trait 仪式)
3. **借用用关键字**: `ref` / `mut ref` 是普通关键字,与后置类型风格统一(`x: ref T`)
4. **零显式生命周期**: 借用区域由编译器推断,绑定于创建它的词法块;区域只在**错误信息**中出现(以人类可读语言描述:"这个借用超出了创建它的代码块")
5. **结构体不持有借用**: 需要共享数据时,显式使用 `Shared[T]`(引用计数、不可变共享,`.clone()` 显式增加引用)

### 6.3 `str` 设计

- `str` 为**不可变、值语义、写时复制 (COW)** 类型(类 Swift `String`),因此不需要 `&str` 切片
- 切子串返回新值:`s.sub(start, end) -> str`(复制)或 `s.slice_view(...) -> Slice[T]`(区域限定的借用视图,后期)
- 这样字符串这一引用大户天然规避了借用语法

### 6.4 设计理由(对 AI 友好)

1. **借用检查是 Rust 中 AI 生成代码失败的头号来源**。去掉符号和显式标注,失败面砍掉一大块
2. `ref`/`mut ref` 是已有概念(C# `ref`、Swift `inout`),AI 类比成本低,不会生成陌生语法
3. "结构体不能持有借用"是**强但简单**的规则: 编译器永远能给出明确替代方案(`Shared[T]` / 移入所有权),错误信息保持可行动
4. 无 GC = 无暂停、行为确定,与 P2 可预测性一致

### 6.5 权衡(诚实记录)

- 代价: Rust 能写的"结构体持引用"场景在 Sole 中要换写法;所有权实现难度显著高于 GC
- 缓解: 该场景在业务代码中占比很小;`Shared[T]` 覆盖绝大多数需求
- 实现风险**: 借用检查器是全部里程碑中最难的部分 → 分两步: M1/M2 实现"移动语义 + 最小借用规则集",M3 补全(见 §10.3)

## 7. 并发模型 (Concurrency)

> 作者决策: **CSP 风格协程 + 结构化并发** —— 类似 Go 的 goroutine + channel,
> 但加入任务树、作用域等待与取消传播,杜绝"fire-and-forget 泄漏"与失控的后台任务(2026-08-11)

### 7.1 模型

- **协程**(轻量用户态任务,M:N 调度到少量 OS 线程上),非 1:1 线程
- **通信通过通道 (channel)**: 发送把值**移入**通道,接收把值**移出** —— 与 §6 所有权模型严丝合缝: 跨任务传数据 = 移动所有权,无共享可变状态,**数据竞争在类型层面不可能发生**("通过通信共享内存")
- **结构化并发**: 任务构成一棵树;父作用域退出前必须等待全部子任务;父级提前退出(return / 错误)→ 取消全部子任务并传播

### 7.2 语法(与既有决策一致)

| 概念 | Sole 语法 | 说明 |
|------|-----------|------|
| 任务组 | `task_group:` + 缩进块 | 块结束前等待全部子任务;提前退出 → 取消子任务 |
| 派生任务 | `go worker(x)` | 在**当前 task_group** 内派生子任务;顶层自动处于隐式组 |
| 通道类型 | `ch: Chan[T]` | 后置类型 + 方括号泛型,与 D2/D4 一致 |
| 创建通道 | `ch = Chan[int]()` | 无缓冲;`Chan[int](10)` = 缓冲 10 |
| 发送 | `ch.send(v)` | **移动语义**: v 的所有权进入通道(Copy 类型除外) |
| 接收 | `v = ch.recv()` | 返回 `Option[T]`(None = 通道已关闭/组被取消) |
| 接收循环 | `for v in ch` | 每次迭代 recv 一个值;`Chan` 为句柄类型,循环不消耗句柄;关闭或取消 → 循环自然结束 |
| 关闭 | `ch.close()` | 关闭后 `send` 返回错误 `Result`;`recv` 取完剩余值后返回 None |

> 注: 通道操作全部是**显式方法调用**,无 `<-` 之类的符号 —— 与"禁魔术方法 + 无神秘符号"的语法决策一致。

### 7.3 结构化并发的具体规则

1. `go` 只能出现在 `task_group` 内;顶层脚本自动处于一个**隐式 task_group**(程序结束前自动等待全部顶层任务)
2. **子任务生命周期 ⊆ 所属组的作用域** → 借用检查与并发天然兼容: 子任务只能借用组内可见的数据,编译器可验证(结构化是借用检查器的恩人)
3. **取消 = 关闭**: 组提前退出 → 取消子任务 → 等效于关闭其依赖的通道 → 阻塞中的 `recv`/`send` 立即返回,`for` 循环自然结束
4. **协作式调度**: 仅在通道操作与显式 `yield` 处切换(无抢占中断)→ 行为可预测,符合 P2
   - 代价(诚实记录): CPU 密集循环不主动让出会饿死其他任务 → 需要显式 `yield`(标准库约定)

### 7.4 与所有权模型的关系(本设计最大的协同点)

- send/recv = 所有权跨任务移动 → **无共享可变状态,数据竞争不可能**(无需加锁思维)
- `Shared[T]`(§6)为**原子引用计数**(类 Arc),可安全跨任务共享不可变数据
- 可变共享数据(罕见): 标准库 `Mutex` 显式 `lock()`/`unlock()`(方法调用,无语法魔法);初版可后置

### 7.5 初版不做

- ❌ `select` 多路复用(Go select)初版不做 —— 等真实需求;`for` 循环 + 取消已覆盖大部分场景
- ❌ 不直接暴露 OS 线程(由运行时调度器管理)
- ❌ 无逃逸任务(fire-and-forget)—— 结构化并发的核心承诺,不做例外

### 7.6 权衡(诚实记录)

- 结构化并发牺牲 Go 的"自由 spawn": 后台长跑任务必须显式组织(顶层隐式组 + 显式组等待)
- 协作式调度: 可预测但需 yield 纪律;真实性能压力出现后再评估是否引入抢占(记录于 §11)

## 8. 标准库目标 (Stdlib)

- **小而精**: 核心库仅覆盖: 集合、文本、IO、时间、数学、JSON、网络(HTTP)、测试、并发原语
- **命名一致性**: 同义操作全局同名(`len()`、`to_str()`、`parse()`),API 可猜测性优先
- **无隐式导入**: 一切导入显式(不做 Python 式内置魔法的隐式全局)
- **内置测试原语**: `test` 块 / `assert`,让 AI 代理能自己验证自己写的代码
- 第三方包管理: 预留(为语言的成功做准备,不阻塞初版)

## 9. 工具链与 AI 集成 (Tooling & AI)

### 9.1 必备工具(按优先级)
1. **编译器/解释器本体**: 快速启动、增量编译(< 100ms 反馈循环)
2. **formatter**: 官方唯一格式(类 gofmt)。AI 输出永远不用纠结风格
3. **LSP**: 补全、跳转、诊断。AI 与人都靠它获得即时反馈
4. **测试运行器**: 与 LSP 联动
5. **调试器**(后期)

### 9.2 AI 友好设计
- **错误信息规范**: 每条编译错误必须包含 —— `稳定错误码(E00xx 词法 / E01xx 解析 / E02xx 求值 / E03xx 类型检查)` + `位置` + `原因` + `修复建议` + `正确示例`(结构化,可被 AI 解析)
- **错误信息双语**: 默认英文,`--lang zh` 或环境变量 `SOLE_LANG=zh` 切换中文;错误 = 数据(错误码 + 参数),语言仅为渲染层(`sole-diag` crate);关键字/标识符保持英文-only
- **示例库**: 每个语法特性配 2-3 个 golden 示例,作为 AI 的"few-shot 语料"
- **常见错误对照表**: 维护一份"AI 常犯错误 → 正确写法"文档(初期手动,后期从 issue 提炼)
- **文档机器可读**: spec 与 API 文档结构化(可编译为 JSON),便于 AI 检索
